# koni-qc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. This is a **docs/methodology skill** (no scripts/TDD) — tasks are doc-authoring + a pilot + an author-blind review + the koni-harness ship.

**Goal:** Ship `skills/koni-qc/` — a compose-first QC methodology skill that turns koni-docs inputs into Silicon-Valley-grade, fully-traceable test documentation (covering all cases + edge cases) and drives QC execution, delegating templates→koni-docs, execution→gstack, gate/loop→koni-harness.

**Architecture:** SKILL.md orchestrator + 6 methodology references + one pilot example. It contributes the coverage-intelligence (test-design techniques, edge taxonomy, the mandatory AC↔TC matrix, NFR/security, risk-based priority, a quality-bar rubric) and invokes the existing skills for templates/execution/gate. Synthesizes two surveyed corpora: `koni-docs.backup` (weak baseline to beat — 12 gaps) and `Koni-Finance` (production standard to codify — rich per-TC table + dedicated security).

**Tech Stack:** Markdown only. Verified by self-grade against the rubric + an author-blind review subagent (no test suite — no executable code). Built by dogfooding the koni-harness loop (`loop.sh` tracks US-5.1; `gate` at commit).

### Task 1: The six methodology references

Author all six together so cross-references are consistent. Each is prose; write
real, tight content (a shipped methodology, not stubs). Match the spec §4.

- [ ] **Step 1 — `references/test-design.md`** (spec §4.1). Sections: `## Deriving
  cases from an AC` (the procedure), then one `##` per technique — equivalence
  partitioning, boundary-value analysis, decision tables, state-transition,
  pairwise/combinatorial, error-guessing — each with: what it is, when to use,
  and a worked 2–3-line example turning one AC into positive+negative+boundary
  cases.

- [ ] **Step 2 — `references/edge-coverage.md`** (spec §4.2). A `## The edge-case
  taxonomy` checklist with one row per class — null/empty/zero/max/overflow ·
  malformed/encoding/emoji/i18n · injection/XSS/special-chars ·
  concurrency/double-submit/race · permission/auth/ownership ·
  network flaky/offline/timeout/retry · state/lifecycle transitions ·
  timezone/locale · idempotency · pagination/large-data — each naming the
  backup gap it closes and a one-line example case. Plus a `## How to apply`
  (run every feature through the list; budget ≥50% negative/boundary).

- [ ] **Step 3 — `references/traceability.md`** (spec §4.3). Sections:
  `## TC-ID scheme` (`TC-<EPIC>.<TYPE>-<n>`, TYPE ∈ E2E/FUNC/API/REG/SMK/SEC/
  PERF/A11Y; domain prefixes allowed); `## The canonical test-case table` — the
  exact columns adopted from Koni-Finance: `TC-ID | Name | Priority | Test data |
  Preconditions | Action/Request | Expected | Actual | Status | Perf |
  Side-effects | Covered-by` with a 2-row filled example; `## AC↔TC coverage
  matrix` — the MANDATORY matrix (columns `Story | AC | AC description | TC(s) |
  Types covered`), the rule **every AC has ≥1 positive AND ≥1 negative AND ≑1
  boundary TC; no orphan AC, no orphan TC**, and that the matrix is the gate;
  `## Risk-based priority & regression` — priority = impact×likelihood, run-order
  under time pressure, `RC-` regression tagging for the release baseline;
  `## koni conventions preserved` — platform-variant columns, L1/L2/L3 hierarchy,
  preconditions, issue links, native-language steps allowed.

- [ ] **Step 4 — `references/nfr.md`** (spec §4.4). Security FIRST:
  `## Security` (authn/authz, token storage/rotation, CSRF/SameSite,
  replay/nonce, rate-limiting, RLS/data-isolation, injection — codifying the
  Koni-Finance dedicated security suite; note koni-qc can emit a standalone
  `*-security-test-cases.md`). Then `## Performance` (with **SLA targets**, not
  just measured times), `## Accessibility` (WCAG: keyboard, screen-reader,
  contrast), `## Internationalization`, `## Reliability & resilience`
  (failure-mode tests), `## Compatibility` (cross-platform/browser),
  `## Observability`. Each: a short checklist + when risk makes it required.

- [ ] **Step 5 — `references/qc-workflow.md`** (spec §4.5). The lifecycle as five
  `##` stages — Frame / Design / Self-review / Execute / Release gate — each
  naming the exact delegate it invokes (Frame→koni-harness `sprint.sh` + read
  koni-docs inputs; Design→author into koni-docs `docs/tests/test-cases/EPIC-N.md`
  using test-design+edge+nfr+traceability; Self-review→`quality-bar.md`;
  Execute→gstack `qa`/`investigate`/`browse`, record into koni-docs
  `test-report.md`; Release gate→entry/exit criteria + koni-docs release report +
  koni-harness `gate`). Include `## Entry / exit criteria`, `## Test-data &
  fixtures strategy`, `## Test lifecycle` (active/deprecated/archived).

- [ ] **Step 6 — `references/quality-bar.md`** (spec §4.6). A scored rubric in
  three bands: `## Band A — beat the backup (must clear all)` (12 items: explicit
  TC IDs · AC↔TC matrix · ≥50% negative+boundary · NFR present · coverage matrix ·
  test-data strategy · entry/exit · lifecycle · risk order · regression scope ·
  automation linkage · real reports); `## Band B — match the Koni-Finance
  standard` (rich per-TC metadata · dedicated security · concrete test data ·
  execution instrumentation); `## Band C — close its residual gaps` (full AC↔TC
  matrix · env/fixtures playbook · a11y/i18n · perf SLA · cadence). State the
  pass rule: clear all of A, demonstrably exceed B and C.

- [ ] **Step 7: Commit**

```bash
git add skills/koni-qc/references
git commit -m "docs(koni-qc): methodology references (test-design, edge, traceability, nfr, workflow, quality-bar)"
```

### Task 3: Pilot — `customize-network` test-cases doc

Demonstrates the standard end-to-end and the uplift over the backup's 58 manual
cases. Author into the koni-docs test-cases shape (story/AC-centric 10-section)
filled with the canonical rich-TC table + the AC↔TC matrix + edge/NFR/security.

**Pilot input (the feature's requirements, distilled from the survey of the
backup `customize-network` suite — the implementer treats these as the AC):**
- Import a network manually: open Manage Network → add (+) → enter RPC URL → app
  auto-detects chain type (EVM/Substrate) and auto-fills name / symbol / decimals
  / chain-id / block-explorer → user may override → Save → network appears in the
  provider/selector.
- Validation: RPC must be reachable; reject unreachable/invalid RPC with a clear
  error ("Cannot connect to this provider"); reject a network that already exists.
- Edit / delete a custom network; cannot delete a built-in/active network in use.
- Platform variants: extension + mobile.

- [ ] **Step 1 — Write `skills/koni-qc/references/examples/customize-network-test-cases.md`**
  following the koni-docs `test-cases/EPIC-N.md` 10-section structure, with:
  - `## Scope` (in/out) + `## Acceptance criteria` (number them AC-1..AC-n from
    the requirements above).
  - `## Test cases` using the **canonical rich-TC table** — include, beyond the
    happy path: negative (unreachable RPC, malformed URL, duplicate network),
    **boundary** (max-length name, decimals 0 / max, very long URL), **injection**
    (`<script>` / quotes / SQL-ish in name & URL), **encoding/emoji/i18n** name,
    **concurrency** (double-tap Save), **network-failure** (flaky/offline/timeout
    during detect), **permission/state** (delete an in-use network), and an
    **NFR/security** sub-section (RPC URL sanitized; detect responds < SLA;
    keyboard-navigable form). Give each a real TC-ID (`TC-CN.FUNC-1`,
    `TC-CN.SEC-1`, …), priority, concrete test data, preconditions, expected.
  - `## Coverage matrix` — every AC → its TC IDs, showing each AC has positive +
    negative + boundary coverage (the thing the backup lacked).
  - `## Before/after delta` — a short note: backup = 58 cases, ~70% happy-path, no
    IDs/matrix/NFR; koni-qc = N cases with explicit IDs, full AC↔TC matrix, the
    added negative/boundary/injection/NFR/security classes, risk-ordered.

- [ ] **Step 2: Commit**

```bash
git add skills/koni-qc/references/examples/customize-network-test-cases.md
git commit -m "docs(koni-qc): pilot — customize-network test-cases (uplift over the manual backup suite)"
```
