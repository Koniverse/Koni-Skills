# Skill inventory — what every Koniverse repo installs

This is the concrete answer to "which AI skills do I install?" — derived from
auditing the six reference repos (`koni-devops`, `Koni-ERP-02`, `koni-growth`,
`koni-landing`, `koni-training`, `Senti-Quant`). Install the **baseline** in
every repo, then add the **per-profile** packs.

Each skill set comes from a *different source and install mechanism* — that's
the part most setups get wrong. Match the mechanism, not just the name.

## Install mechanisms (4 sources)

| Source | Mechanism | Lands in | Updates |
|---|---|---|---|
| **BMAD** | `npx bmad-method install` (interactive; answers saved in `_bmad/config.toml`) | `.claude/skills/bmad-*` (vendored real dirs) + `_bmad/` framework | re-run installer |
| **koni-docs** | symlink from shared `Koni-Skills`, **or** `skills-lock.json` `sourceType: github` (`Koniverse/Koni-Skills`) | `.agents/skills/koni-docs` + `.claude/skills/koni-docs` | `git pull` shared repo, or re-resolve lockfile |
| **gstack** | installed **globally**, once per machine | `~/.claude/skills/{gstack,_gstack-command,gstack-upgrade,open-gstack-browser}` | `/gstack-upgrade` |
| **Anthropic skills** | vendored / skill-install | `.claude/skills/<name>` (real dirs) | re-vendor |

gstack is **global, not per-repo** — never copy it into a repo. If
`~/.claude/skills/gstack` exists, the repo already has it. Only `koni-docs` and
the BMAD pack are wired per-repo.

## Baseline — every repo

### 1. koni-docs (the documentation framework)
Wire per-repo via symlink or lockfile (see [`skill-wiring.md`](skill-wiring.md)).
Present in 5/6 reference repos — the lone exception is `koni-landing` (pure
design/landing repo with no sprint workflow). **Install it unless the repo has
no sprints/docs lifecycle at all.**

### 2. BMAD standard pack (~40 skills)
Generated by `npx bmad-method install`. The pack that appears in every repo
(`koni-devops` / `Koni-ERP-02` / `koni-growth` / `koni-landing` all carry this
near-identical set):

### 3. gstack (global)
Confirm `~/.claude/skills/gstack` exists. If missing, install globally once —
not into the repo. Provides `/browse`, `/design-review`, `/deep-research`,
review / qa / cso, etc.

## Per-profile additions

### code (`Koni-ERP-02`, `Senti-Quant`)
- BMAD code/test extensions seen in repos: `bmad-investigate`, `bmad-spec`,
  `bmad-ux`, `bmad-prd` (devops/erp), and on Senti-Quant the full
  `bmad-testarch-*` (8: atdd/automate/ci/framework/nfr/test-design/test-review/trace)
  and `bmad-wds-*` web-design-system packs — selected via the `bmad-method`
  installer's module answers, not added by hand.
- UI repos vendor **shadcn** (`.claude/skills/shadcn` + `.agents/skills/shadcn`).
  Rule of thumb: if the repo renders a UI (React/Next/Vue components, a
  `components.json`, or a `tailwind.config`), vendor shadcn. A backend-only
  service (API, worker, MT5 bot) skips it. When UI is plausible but unconfirmed,
  ask rather than scaffolding it blindly.
- Test-tooling skills on Senti-Quant: `gen-testcase`, `lint-testcase`,
  `run-test`, `sync-testcase` (project-local).
- gstack assumed present globally (code repos lean on `/review`, `/qa`).

### content (`koni-growth`, `koni-landing`, `koni-training`)
- BMAD content variant adds `bmad-create-ux-design`, `bmad-distillator`
  (growth/landing).
- `koni-training` vendors the **Anthropic skills** for document & design work:
  `docx`, `pptx`, `pdf`, `xlsx`, `frontend-design`, `web-artifacts-builder`,
  `webapp-testing`, `mcp-builder`, `brand-guidelines`, `canvas-design`,
  `theme-factory`, `claude-api`, `doc-coauthoring`, `internal-comms`,
  `algorithmic-art`, `slack-gif-creator`, `skill-creator`.
- Marketing/landing repos also lean on global marketing skills (copywriting,
  page-cro, seo-audit, social-content) — these are global, like gstack.

### devops (`koni-devops`)
- Same baseline (BMAD pack + koni-docs). No special per-repo skill vendoring;
  the work is shell + deploy, driven by gstack + bmad planning skills.

## Install order during bootstrap

1. Confirm **gstack** is global (`ls ~/.claude/skills/gstack`); install once if not.
2. Run `npx bmad-method install` → lays down `_bmad/` + the BMAD pack +
   `config.toml` (set `output_folder = "_bmad-output"`, language English).
3. Wire **koni-docs** per [`skill-wiring.md`](skill-wiring.md).
4. Profile extras: vendor **shadcn** (UI code repos) / **Anthropic skills**
   (content repos) as the matching reference repo does.
5. Verify counts: `ls .claude/skills | wc -l` should land in the 40s (code/devops)
   to 60+ (content/training with Anthropic skills).

## Audit (onboard) — is the skill set installed?

```bash
echo "bmad pack: $(ls .claude/skills/bmad-* 2>/dev/null | wc -l | tr -d ' ') skills"
test -e .claude/skills/koni-docs && echo "koni-docs ✅" || echo "koni-docs ⬜"
test -d ~/.claude/skills/gstack && echo "gstack (global) ✅" || echo "gstack ⬜ install globally"
test -d _bmad && echo "_bmad framework ✅" || echo "_bmad ⬜ run: npx bmad-method install"
```

A repo with `koni-docs` but **0** `bmad-*` skills means `bmad-method install`
was never run — that's the most common onboarding gap.
